We are going to build a **high-end, production-grade website inspired by the quality, visual impact, animations, interactions, and conversion-focused design of https://klientboost.com/**.

The goal is NOT to copy the website. Use it as a **design and experience benchmark** for the level of quality we want to achieve.

Before writing or implementing any code, I want you to **plan, define, and document the complete system architecture and engineering standards for this project**.

The final system must be:

* Production-grade
* Scalable
* Secure
* Highly performant
* SEO-friendly
* Accessibility-compliant
* Fully responsive
* Conversion-focused
* Easy for developers to understand and extend
* Easy to integrate with future services
* Easy to maintain for years
* Structured so that new developers can join the project and understand it quickly
* Designed to prevent avoidable production mistakes

Do not jump directly into implementation. First establish the architecture, standards, conventions, documentation, development workflow, deployment strategy, and quality gates.

## 13. Git & GitHub Engineering Rules

Establish strict Git/GitHub standards.

The development workflow must include rules such as:

1. Always pull the latest `main` before beginning work.
2. Never directly push unfinished work to `main`.
3. Use feature branches.
4. Keep commits focused and meaningful.
5. Never commit secrets, `.env` files, credentials, API keys, build artifacts, or unnecessary files.
6. Open pull requests for changes.
7. Run all required validation checks before pushing.
8. Never merge code that fails required checks.
9. Resolve merge conflicts carefully.
10. Keep `main` production-ready at all times.

Define:

* Branch naming
* Commit conventions
* Pull-request conventions
* Code review requirements
* Merge strategy
* Branch protection
* Required checks
* Release tagging
* Rollback process
